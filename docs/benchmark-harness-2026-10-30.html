Configuración recomendada

🎯 Orquestador

Claude Sonnet — 3.8K tokens/tarea, disciplina perfecta de instrucciones (idioma, alcance). Opus 5.5 nativo solo para arquitectura crítica.

🔨 Obrero principal

mcode — mejor calidad por token (150K totales en 2 tareas vs 571K de cmdc). Alternativa rápida: cheap-explore.

🔍 Exploración

cheap-explore (opencode/nan) — 1.3min por tarea, comunicación estable probada en runs largos.

🧠 Análisis profundo

mimo-v2.6-pro (con workspace) o agy38 — asumiendo costo alto. argon (1M ctx) como reemplazo de Claude si la cuota aprieta.

Hallazgos clave del ciclo completo:
  • Ningún harness delegó internamente en tareas acotadas — el multi-agente solo aparece cuando se le exige (sonda obligada: los 4 confirmaron con tool_use real en logs).
  • La varianza run-a-run de mcode (23K vs 48K tokens, mismo modelo) es mayor que la diferencia entre modelos: el harness importa más que el modelo de fondo.
  • mcode ignora overrides de modelo (router fijado a glm5.3-flash); deepseek-v4.1-flash en mcode no es posible hoy.
  • Opus vía agy cuesta 12x más tokens que vía Claude nativo: evitar wrappers para el mismo modelo.
  • El fix del arnés (S1: key cloud a localhost) fue aplicado y subido a main durante este ciclo (PR #563).
